# 사용자별 메뉴 접근 권한 구현 가이드

## 1. 개요 및 요구사항

### 1.1 목적
프로그램관리·메뉴관리·그룹관리·권한관리를 통해 구성한 데이터를 사용하여, **로그인 사용자에게만** 권한별로 접근 가능한 메뉴를 왼쪽 사이드바에 표시하는 기능을 구현하기 위한 절차 및 명세를 정의한다. **비로그인 시에는 접근 가능한 메뉴가 없으며, 모든 메뉴는 로그인 후에만 접근 가능**하다.

### 1.2 요구사항 정리

| 번호 | 요구사항 | 설명 |
|------|----------|------|
| 1 | API 인자 | **userId**, **cmpnyCd**, **langGb** 모두 **필수** |
| 2 | 회사 | 로그인 사용자는 **한 회사만** 사용 (단일 회사) |
| 3 | 하드코딩 제거 | 사이드바의 **하드코딩된 메뉴 전부 제거**, DB·API 기반으로만 표시 |
| 4 | 메뉴 링크 | **CM_MENU**의 **PROGRM_FILE_NM** 및 접근 경로(URL) 사용, 현재 소스의 하드코딩 메뉴를 DB에 넣는 방법 명시 |
| 5 | 관리자 | 관리자(ADM)도 **권한 기반으로만** 메뉴 표시 (관리자 전용 전체 메뉴 없음) |
| 6 | 비로그인 | **비로그인 시 접근 가능한 메뉴 없음**. **모든 메뉴는 로그인 후에만** 접근 가능 |

## 2. 관련 테이블 구조

### 2.1 메뉴·권한 관련 테이블

| 테이블 | 설명 |
|--------|------|
| **CM_MENU** | 메뉴 트리 (회사별, MENU_ID, 상위메뉴, 프로그램파일명=접근경로, 메뉴명코드, 정렬 등) |
| **CM_AUTHOR** | 권한 마스터 (회사, 권한코드) |
| **CM_AUTHOR_USER** | 권한-사용자/그룹 연결 (USER_TY: 'USER' 직접, 'ROLE' 그룹 / USER_CD: 사용자ID 또는 그룹ID) |
| **CM_AUTHOR_MENU** | 권한별 메뉴 (권한에 허용된 MENU_ID 목록) |
| **CM_GROUP_USER** | 그룹 소속 (CMPNY_CD, GROUP_ID, MBRSH_SQ) |
| **CM_USER_ORGNZT_MBRSH** | 사용자 소속 (CMPNY_CD, USER_ID, MBRSH_SQ) |
| **CM_MESSAGE_LANG** | 다국어 메시지 (메뉴명: LANG_KEY = MENU_NM_CD, MESSAGE_CN = 표시명) |
| **CM_PROGRM** | 프로그램(화면) 마스터 (회사별, 프로그램파일명=접근경로, 프로그램명코드, URL, 설명 등) |

### 2.2 CM_MENU 컬럼 (요약)

| 컬럼 | 설명 |
|------|------|
| CMPNY_CD | 회사코드 |
| MENU_ID | 메뉴 ID (PK 일부) |
| MENU_NM_CD | 메뉴명 메시지 키 (CM_MESSAGE_LANG.LANG_KEY와 매핑) |
| PROGRM_FILE_NM | **실제 접근 경로(URL 경로)**. 폴더(디렉터리)인 경우 `dir` |
| UPPER_MENU_ID | 상위 메뉴 ID (최상위는 `#`) |
| SORT_ORD | 정렬 순서 |
| USE_FL | 사용 여부 |

- **PROGRM_FILE_NM**: 프론트에서 그대로 링크(to)로 사용할 값. 예: `/tvframework/support/download`
- **MENU_NM_CD**: 해당 회사·언어의 메뉴 표시명은 **CM_MESSAGE_LANG**에서 LANG_KEY = MENU_NM_CD, LANG_CODE = langGb 로 조회한 MESSAGE_CN 사용

### 2.3 CM_PROGRM 컬럼 (요약)

| 컬럼 | 설명 |
|------|------|
| CMPNY_CD | 회사코드 (PK) |
| PROGRM_FILE_NM | 프로그램 파일명 = **접근 경로(URL)** (PK). CM_MENU의 PROGRM_FILE_NM과 동일한 값 사용 |
| PROGRM_STRE_PATH | 프로그램 저장 경로 (선택, 비워둘 수 있음) |
| PROGRM_NM_CODE | 프로그램명 메시지 키 (CM_MESSAGE_LANG.LANG_KEY와 매핑) |
| PROGRM_URL | 프로그램 URL (접근 경로와 동일하게 넣는 경우가 많음) |
| PROGRM_DC | 프로그램 설명 |
| USE_FL | 사용 여부 |
| CREATION_ID, CREATION_DT, UPDATE_ID, UPDATE_DT | 등록/수정 정보 |

- **PROGRM_FILE_NM**: CM_MENU에 등록한 **실제 화면 경로**와 1:1로 맞추면 된다. `dir`(폴더)인 메뉴는 CM_PROGRM에 넣지 않는다.
- **PROGRM_NM_CODE**: 메뉴명과 동일한 메시지 키(예: menu.support.download)를 쓰면 CM_MESSAGE_LANG 한 건으로 메뉴명·프로그램명을 함께 쓸 수 있다.

## 3. 현재 하드코딩 메뉴를 DB에 넣는 방법

### 3.1 트리 구조 및 PROGRM_FILE_NM(접근 경로) 매핑

현재 소스의 **LeftSidebar** 및 **url.tsx** 기준으로, 아래와 같이 **MENU_ID**, **UPPER_MENU_ID**, **PROGRM_FILE_NM(URL 경로)**, **MENU_NM_CD(메시지키)** 를 정의한다.  
(회사는 단일 회사 사용이므로 예시는 CMPNY_CD = `'001'` 기준으로 기술한다. 실제 적용 시 사용하는 회사코드로 치환.)

- **최상위**: UPPER_MENU_ID = `'#'`
- **폴더(자식만 있고 자신은 링크가 없는 구간)**: PROGRM_FILE_NM = `'dir'`
- **실제 화면 링크**: PROGRM_FILE_NM = url.tsx에 정의된 **전체 경로**

### 3.2 CM_MESSAGE_LANG 등록 (메뉴명)

메뉴 표시명은 **CM_MESSAGE_LANG**에 LANG_KEY = MENU_NM_CD, LANG_CODE = 언어코드(예: ko_KR), MESSAGE_CN = 표시문자열 로 넣는다.  
예시(일부):

```sql
-- CMPNY_CD, LANG_KEY, LANG_CODE, MESSAGE_CN (필수 컬럼만 예시)
INSERT INTO CM_MESSAGE_LANG (CMPNY_CD, LANG_KEY, LANG_CODE, MESSAGE_CN) VALUES ('001', 'menu.main', 'ko_KR', '홈');
-- ... 위 CM_MENU의 모든 MENU_NM_CD에 대해 동일하게 등록
INSERT INTO CM_MESSAGE_LANG (CMPNY_CD, LANG_KEY, LANG_CODE, MESSAGE_CN) VALUES ('001', 'menu.system', 'ko_KR', '시스템관리');
INSERT INTO CM_MESSAGE_LANG (CMPNY_CD, LANG_KEY, LANG_CODE, MESSAGE_CN) VALUES ('001', 'menu.system.message', 'ko_KR', '다국어관리');
INSERT INTO CM_MESSAGE_LANG (CMPNY_CD, LANG_KEY, LANG_CODE, MESSAGE_CN) VALUES ('001', 'menu.system.user', 'ko_KR', '사용자관리');
INSERT INTO CM_MESSAGE_LANG (CMPNY_CD, LANG_KEY, LANG_CODE, MESSAGE_CN) VALUES ('001', 'menu.system.user.password', 'ko_KR', '사용자 암호변경');
-- ... (위 CM_MENU의 나머지 MENU_NM_CD에 대해 동일하게 등록)
```

- 실제 테이블 컬럼명/제약조건에 맞게 INSERT 문을 조정한다.
- 영문(en_US) 등 추가 언어가 필요하면 동일 LANG_KEY에 LANG_CODE만 바꿔서 추가한다.

## 4. 사용자별 접근 가능 메뉴 조회 쿼리

### 4.1 인자 (모두 필수)

| 파라미터 | 타입 | 설명 |
|----------|------|------|
| userId | String | 로그인 사용자 ID (로그인 사용자 전용 API이므로 필수. “비로그인용” 처리) |
| cmpnyCd | String | 회사코드 (단일 회사 사용) |
| langGb | String | 언어코드 (메뉴명 조회용, 예: ko_KR) |

### 4.2 1단계: 사용자가 가진 (CMPNY_CD, AUTHOR_CD) 목록

- **직접 권한**: CM_AUTHOR_USER 에서 USER_TY = 'USER', USER_CD = userId
- **그룹을 통한 권한**: CM_AUTHOR_USER(USER_TY='ROLE') + CM_GROUP_USER + CM_USER_ORGNZT_MBRSH(USER_ID = userId)

```sql
SELECT DISTINCT AU.CMPNY_CD, AU.AUTHOR_CD
FROM CM_AUTHOR_USER AU
WHERE AU.USER_TY = 'USER' AND AU.USER_CD = #{userId}
  AND AU.CMPNY_CD = #{cmpnyCd}

UNION

SELECT DISTINCT AU.CMPNY_CD, AU.AUTHOR_CD
FROM CM_AUTHOR_USER AU
INNER JOIN CM_GROUP_USER GU
  ON GU.CMPNY_CD = AU.CMPNY_CD AND GU.GROUP_ID = AU.USER_CD AND GU.USE_FL = 'Y'
INNER JOIN CM_USER_ORGNZT_MBRSH M
  ON M.CMPNY_CD = GU.CMPNY_CD AND M.MBRSH_SQ = GU.MBRSH_SQ AND M.USER_ID = #{userId} AND M.USE_FL = 'Y'
WHERE AU.USER_TY = 'ROLE'
  AND AU.CMPNY_CD = #{cmpnyCd};
```

### 4.3 2단계: 접근 가능 MENU_ID

1단계 결과와 CM_AUTHOR_MENU를 조인해 해당 권한들에 연결된 MENU_ID를 구한다.

```sql
SELECT DISTINCT AM.MENU_ID
FROM CM_AUTHOR_MENU AM
INNER JOIN (
  -- 4.2 1단계 쿼리 전체
) AUTH ON AUTH.CMPNY_CD = AM.CMPNY_CD AND AUTH.AUTHOR_CD = AM.AUTHOR_CD
WHERE AM.CMPNY_CD = #{cmpnyCd};
```

### 4.4 3단계: 접근 가능 메뉴만으로 트리 구성 (사이드바용)

- 2단계에서 구한 MENU_ID 집합 + **그 상위 노드(UPPER_MENU_ID 재귀)** 까지 포함한 메뉴만 조회해야 트리가 끊기지 않는다.
- **CM_MENU** + **CM_MESSAGE_LANG**(LANG_KEY = MENU_NM_CD, LANG_CODE = langGb) 조인으로 메뉴명(menuNm) 조회.
- 정렬: PATH 또는 UPPER_MENU_ID + SORT_ORD 유지.

구체적인 3단계 쿼리는 “접근 가능 MENU_ID + 상위 경로”를 서브쿼리/CTE로 만든 뒤, 기존 selectMenuTree와 유사한 재귀 CTE에서 **해당 MENU_ID 집합에 속하는 노드만** 포함하도록 조건을 걸면 된다. (또는 애플리케이션에서 2단계 MENU_ID 목록을 받아, 기존 메뉴 트리 조회 결과를 필터링하는 방식도 가능.)

## 5. API 명세 (사이드바용 메뉴 트리)

### 5.1 사용자별 접근 가능 메뉴 트리 (로그인 전용)

- **URL**: 예) `GET /api/menu/sidebar` 또는 `GET /cmmnMenu/sidebar`
- **필수 쿼리 파라미터**: **userId**, **cmpnyCd**, **langGb**
- **동작**: 4.2 → 4.3 → 4.4 순서로 “해당 사용자가 접근 가능한 메뉴만” 트리로 반환. (관리자도 동일하게 권한 기반만 표시.) **로그인한 사용자만 호출**하며, 비로그인 시에는 이 API를 호출하지 않고 메뉴를 표시하지 않는다.
- **응답**: 트리 구조(메뉴 ID, 상위 메뉴 ID, 정렬, 메뉴명, **PROGRM_FILE_NM(접근 경로)** 등). 프론트는 **PROGRM_FILE_NM**을 그대로 링크(to)로 사용.

## 6. 프론트엔드 수정 요약

### 6.1 하드코딩 메뉴 전부 제거

- **LeftSidebar** 등에서 **고객지원·시스템관리·사이트관리** 등 **고정 메뉴 목록 및 고정 경로**를 제거한다.
- 대신 **로그인한 사용자에 한해** 5.1 API (userId, cmpnyCd, langGb 필수)를 호출한 결과만 사이드바에 표시한다.

### 6.2 비로그인 처리

- **비로그인 시에는 접근 가능한 메뉴가 없다.** 사이드바에는 메뉴 트리를 표시하지 않거나, 빈 메뉴 영역 + 로그인 유도 문구/버튼만 노출한다. **모든 메뉴는 로그인 후에만** 5.1 API로 권한 기반 메뉴를 받아와 표시한다. (관리자도 동일하게 권한 기반만 표시.)

### 6.3 메뉴 링크

- 각 메뉴의 **링크**는 **CM_MENU.PROGRM_FILE_NM** 값(접근 경로)을 그대로 사용한다.
- `PROGRM_FILE_NM = 'dir'` 인 항목은 폴더이므로 클릭 시 자식 펼치기/접기만 하고, 링크 이동은 하지 않는다.

### 6.4 회사·언어

- 로그인 사용자: **한 회사만 사용**하므로, 로그인 정보(또는 세션)에서 cmpnyCd, userId, langGb를 꺼내 5.1 API에 필수 인자로 넘긴다.

## 7. 절차별 구현 순서

아래 순서대로 진행하면 요구사항(1~6)을 만족하는 “사용자별 메뉴 접근 권한 + 비로그인 시 메뉴 없음(모두 로그인 필수)” 구성을 만들 수 있다.

### 7.1 DB 및 초기 데이터

1. **CM_MENU**  
   - 3.1.2 절의 INSERT로 현재 하드코딩된 메뉴 전부 등록 (PROGRM_FILE_NM = 접근 경로, 폴더는 `dir`).
2. **CM_MESSAGE_LANG**  
   - 3.2 절처럼 각 MENU_NM_CD에 대해 메뉴 표시명 등록 (ko_KR 등).
3. **권한·그룹·사용자**  
   - 권한관리에서 권한 생성 후, CM_AUTHOR_MENU에 허용할 MENU_ID 등록.  
   - 그룹관리에서 그룹 생성 후 그룹에 사용자 연결.  
   - 권한관리에서 권한에 사용자 또는 그룹(ROLE) 연결.  
   - 로그인 사용자는 한 회사만 사용하므로, 해당 회사 기준으로 위 데이터가 일치하는지 확인.

### 7.2 백엔드

4. **사용자별 접근 (CMPNY_CD, AUTHOR_CD) 쿼리**  
   - 4.2 절 쿼리를 매퍼에 등록 (예: selectUserAuthorList 또는 동일 로직).
5. **접근 가능 MENU_ID 쿼리**  
   - 4.3 절 로직을 매퍼에 등록 (1단계 결과 + CM_AUTHOR_MENU 조인).
6. **접근 가능 메뉴 트리 쿼리**  
   - 4.4 절: 접근 가능 MENU_ID + 상위 노드 포함, CM_MESSAGE_LANG 조인, 정렬. (재귀 CTE 또는 기존 트리 쿼리 + 필터.)
7. **사이드바 메뉴 API (로그인 전용)**  
   - 5.1: **userId, cmpnyCd, langGb** 필수 쿼리 파라미터로 받아, 위 쿼리들로 “권한 기반 메뉴 트리”만 반환. (관리자도 동일 로직.)
8. (비로그인용 API 없음)  
   - 별도 비로그인 API는 두지 않음.

### 7.3 프론트엔드

9. **LeftSidebar**  
   - 로그인 여부 판단 (예: getSessionItem('loginUser'), userId·cmpnyCd·langGb 확보).
10. **로그인 시**  
    - 5.1 API 호출 (userId, cmpnyCd, langGb 필수) → 응답 트리만 사용해 사이드바 렌더링. 하드코딩 메뉴 전부 제거.
11. **비로그인 시**  
    - 5.1 API를 호출하지 않음. 사이드바에 메뉴 트리를 표시하지 않거나, 빈 영역·로그인 유도만 표시.
12. **링크**  
    - 각 메뉴 항목의 링크는 **PROGRM_FILE_NM** 사용. `dir`이면 링크 없이 펼침/접기만.
13. **경로 자동 펼침**  
    - 현재 path와 PROGRM_FILE_NM(또는 하위 노드 경로)를 비교해, 해당 메뉴 섹션 자동 펼침 처리 유지.

### 7.4 검증

14. **비로그인**  
    - 사이드바에 접근 가능한 메뉴가 전혀 표시되지 않는지(또는 로그인 유도만 노출되는지) 확인.
15. **로그인(일반·관리자)**  
    - 권한에 따라 메뉴가 다르게 보이는지, 관리자도 “권한 기반만” 보이는지 확인.
16. **링크**  
    - 각 메뉴 클릭 시 PROGRM_FILE_NM 경로로 정상 이동하는지 확인.

## 8. 정리

| 항목 | 내용 |
|------|------|
| **인자** | userId, cmpnyCd, langGb 모두 **필수** (로그인 전용 API) |
| **회사** | 로그인 사용자 **한 회사만** 사용 |
| **사이드바** | **하드코딩 메뉴 전부 제거**, DB·API 기반만 사용 |
| **링크** | **CM_MENU.PROGRM_FILE_NM** = 접근 경로(URL), DB 등록 방법은 3.1.2·3.2 절 참고 |
| **관리자** | **권한 기반만** 표시 (동일 API) |
| **비로그인** | **접근 가능한 메뉴 없음**. **모든 메뉴는 로그인 후에만** 접근 가능 |

위 내용대로 DB 데이터 구성, 쿼리, API, 프론트 수정을 적용하면 “사용자별 메뉴 접근 권한” 및 “비로그인 시 메뉴 없음(모두 로그인 필수)” 요구사항을 충족할 수 있다.
