# 시스템관리 메뉴 – 공통모듈 사용 분석

> **목적**: 시스템관리 하위 메뉴 중 공통모듈(`tvframework.com`)을 사용해야 하는데 사용하지 않고 개별로 구현한 케이스 분석 (소스 수정 없이 분석만 수행)

---

## 1. 분석 대상

| 구분 | 백엔드 패키지 | 메뉴명 |
|------|----------------|--------|
| 공통코드 | sym.cmm (CmmnCode*) | 공통코드관리 |
| 다국어 | sym.msg | 다국어관리 |
| 메뉴 | sym.mnu | 메뉴관리 |
| 프로그램 | sym.pgm | 프로그램관리 |
| 그룹 | sym.grp | 그룹관리 |
| 권한 | sym.cmm (CmmnAuthor*) | 권한관리 |

**공통모듈 사용 현황 (정상 사용)**

- 모든 시스템관리 Mapper: `AbstractMapper` 상속 ✓  
- 모든 시스템관리 Service: `AbstractServiceImpl` 상속 ✓  
- 모든 Controller: `IntermediateResultVO` 반환 ✓  

---

## 2. 공통모듈 미사용·개별 구현 케이스

### 2.1 PaginationInfo (페이징 정보)

**공통모듈**

- `tvframework.com.cmm.pagination.PaginationInfo`  
  - 현재페이지, 페이지당 레코드 수, 페이지 사이즈, 전체 레코드 수  
  - `getFirstRecordIndex()`, `getLastRecordIndex()`, `getTotalPageCount()`, `getFirstPageNo()`, `getLastPageNo()`, `hasPreviousPage()`, `hasNextPage()` 등 계산 메서드 제공  

**개별 구현**

- **다국어관리**: `tvframework.sym.msg.dto.CmmnMessageListResponseDTO.PaginationInfo` (내부 정적 클래스)  
- **프로그램관리**: `tvframework.sym.pgm.dto.CmmnProgramListResponseDTO.PaginationInfo` (내부 정적 클래스)  
- **그룹관리**: `tvframework.sym.grp.dto.CmmnGroupListResponseDTO.PaginationInfo` (내부 정적 클래스)  
- **권한관리**: `tvframework.sym.cmm.dto.CmmnAuthorListResponseDTO.PaginationInfo` (내부 정적 클래스)  

위 4개 모두 **필드만 4개**(currentPageNo, recordCountPerPage, pageSize, totalRecordCount) 갖는 동일 구조를 **각 DTO 안에 중복 정의**하고 있음.  
공통 `com.cmm.pagination.PaginationInfo`를 쓰지 않고, 모듈별로 축약된 형태를 따로 만든 **개별 구현 케이스**에 해당함.

---

### 2.2 CodeOptionDTO (코드 옵션 DTO)

**공통/공유 가능한 DTO**

- `tvframework.sym.cmm.dto.CodeOptionDTO`  
  - 필드: `code`, `name`  
  - 공통코드관리 등에서 사용  

**개별 구현(중복)**

- `tvframework.sym.msg.dto.CodeOptionDTO`  
  - 필드: `code`, `name` (구조 동일)  
  - 다국어관리에서 언어 목록·구분 목록 API 응답에 사용  

다국어관리에서도 “코드 + 이름” 옵션만 필요하므로, **sym.cmm.dto.CodeOptionDTO**를 import 해서 쓰면 되는데, **sym.msg 전용 CodeOptionDTO를 별도 패키지에 동일 구조로 정의**한 **중복 구현** 케이스임.

---

### 2.3 ResponseCode (입력값 무결성 오류 등)

**공통모듈**

- `tvframework.com.cmm.ResponseCode` (enum)  
  - SUCCESS(200), AUTH_ERROR(403), DELETE_ERROR(700), SAVE_ERROR(800), INPUT_CHECK_ERROR(900)  

**사용 현황**

- **공통코드관리**: `ResponseCode.INPUT_CHECK_ERROR.getCode()` 직접 사용 ✓  
- **프로그램관리**: `IntermediateResultVO.inputCheckError(null)` 사용 (내부에서 `ResponseCode` 사용) ✓  
- **다국어관리, 메뉴관리, 그룹관리, 권한관리**: Controller에서 900(입력값 무결성 오류) 반환 처리 없음.  
  - 별도 “개별 응답 코드 클래스”를 만든 것은 아니고, 공통 `ResponseCode`/`IntermediateResultVO.inputCheckError`를 **아직 도입하지 않은** 상태로 볼 수 있음.  
  - 향후 동일한 오류 응답 규약을 맞출 때 공통모듈 사용으로 통일하는 것이 좋음.

---

### 2.4 UserDetailsHelper (등록자/수정자 ID)

**공통모듈**

- `tvframework.com.cmm.util.UserDetailsHelper`  
  - 로그인 사용자(LoginVO 등) 조회 → creationId/updateId 등에 사용  

**사용 현황**

- **공통코드관리, 다국어관리, 메뉴관리, 프로그램관리**: Service에서 `UserDetailsHelper.getAuthenticatedUser()`로 creationId 등 설정 후 Mapper에 전달 ✓  
- **그룹관리**: `CmmnGroupServiceImpl.insertGroup()` / `updateGroup()`의 params에 **creationId, updateId를 넣지 않음**.  
  - DTO에는 creationId/updateId 필드가 있으나, Service에서 공통모듈로 로그인 사용자를 조회해 넣는 처리가 없음.  
- **권한관리**: insert/update 시 creationId/updateId를 Service에서 설정하는 코드 없음.  

그룹·권한은 “등록자/수정자”를 두는 설계라면, **UserDetailsHelper를 사용해 공통모듈 방식으로 설정하는 것이 일관됨**. 현재는 그렇게 하지 않고 있어, 공통모듈을 **사용할 수 있는데 사용하지 않은** 케이스로 볼 수 있음.

---

## 3. 요약

| 구분 | 공통모듈 | 개별 구현·미사용 내용 | 해당 메뉴 |
|------|----------|------------------------|-----------|
| **PaginationInfo** | com.cmm.pagination.PaginationInfo | 리스트 응답 DTO마다 동일 4필드의 내부 PaginationInfo 클래스를 별도 정의 | 다국어, 프로그램, 그룹, 권한 |
| **CodeOptionDTO** | sym.cmm.dto.CodeOptionDTO | 동일 구조(code, name)의 CodeOptionDTO를 sym.msg에 중복 정의 | 다국어 |
| **ResponseCode** | com.cmm.ResponseCode | 입력값 무결성(900) 등 공통 응답코드 미사용 | 다국어, 메뉴, 그룹, 권한 (필요 시 통일 여지 있음) |
| **UserDetailsHelper** | com.cmm.util.UserDetailsHelper | 등록/수정 시 로그인 사용자로 creationId/updateId 설정하지 않음 | 그룹, 권한 |

**정리**

- **명확한 개별 구현(중복)**:  
  - **PaginationInfo** – 4개 모듈이 공통 `com.cmm.pagination.PaginationInfo` 대신 각자 내부 클래스로 구현.  
  - **CodeOptionDTO** – 다국어관리가 `sym.cmm.dto.CodeOptionDTO` 대신 `sym.msg.dto.CodeOptionDTO`를 따로 정의.  
- **공통모듈 적용 여지**:  
  - **ResponseCode** – 다국어/메뉴/그룹/권한에서 오류 응답 시 공통 코드·메시지로 통일 가능.  
  - **UserDetailsHelper** – 그룹/권한에서 등록자·수정자 설정 시 공통모듈 사용 가능.

---

## 4. 적용 이력 (공통모듈 반영)

다음 변경이 적용되었습니다.

| 항목 | 적용 내용 |
|------|-----------|
| **PaginationInfo** | 다국어·프로그램·그룹·권한 리스트 응답 DTO에서 `tvframework.com.cmm.pagination.PaginationInfo` 사용. 각 Service에서 공통 클래스로 페이징 정보 설정. |
| **CodeOptionDTO** | 다국어(sym.msg)에서 `tvframework.sym.cmm.dto.CodeOptionDTO` 사용. `sym.msg.dto.CodeOptionDTO` 삭제, MyBatis resultType 및 import 정리. |
| **UserDetailsHelper** | 그룹(CmmnGroupServiceImpl)·권한(CmmnAuthorServiceImpl)에서 `resolveCreationId()` 도입, insert/update 시 creationId·updateId를 로그인 사용자로 설정. 그룹/권한 Mapper XML에서 `#{creationId}`, `#{updateId}` 사용. |
